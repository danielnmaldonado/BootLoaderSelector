Purpose and evidence boundary
-----------------------------
This English record accompanies the v2.33 documentation and project-launch update.
The results below belong to the corrected v2.32 baseline. Rewriting this record
does not constitute a new test run or establish results for a later commit.
Current per-commit results are available in the repository's GitHub Actions runs.

This repository contains application sources, vendored upstream sources, build and
audit helpers, tests and notices. It does not redistribute the legacy macOS binary
toolchain. A catalog of 951 files can verify a separately supplied local copy; it
does not establish the toolchain's redistribution rights or original provenance.

Scope of the completed work
---------------------------
The v2.32 corrections cover application and DevicePathLib resource handling,
sanitizer capability detection, BaseTools diagnostics and checked I/O, native Linux
building, release publication and the Linux/macOS continuous-integration pipeline.
The audit combines direct source review, targeted host regressions, compiler
diagnostics, static analysis, signed EFI builds and an isolated OVMF chainload.
It does not claim that every function of every vendored dependency was manually
audited or that all firmware states and application branches were exercised.

Completed local verification
----------------------------
Environment: Intel x86-64 macOS, Apple Clang 21, GNU GCC 15.3, Python 3.14,
OpenSSL 4.1 and Jsign 7.5. The original external cross-toolchain was supplied
separately and checked against its catalog before execution.

The full quality gate, including a signed release build, passed with
BLS_QUALITY_REPEAT=3. The 18 host test programs ran in these supported modes:

  Clang ASan/UBSan:       18 programs x 3 executions = 54
  GNU GCC UBSan:         18 programs x 3 executions = 54
  Clang ASan/IntegerSan:  18 programs x 1 execution  = 18
  Clang ThreadSanitizer:  18 programs x 1 execution  = 18
  Total:                 144 successful host-program executions

These are repeated executions of 18 programs, not 144 distinct test programs.
Clang LeakSanitizer and GNU GCC ASan/ThreadSanitizer were unavailable on this
local host. Capability probes reported SKIP for these unsupported modes; they
are not counted as passing coverage. Local Clang ASan ran without leak detection.

Additional completed checks:

  - BaseTools deep/bounds/fuzz: two programs per compiler, four executions.
  - Strict compilation and Clang/GNU GCC analysis of all nine application C
    modules, with no remaining actionable findings in the corrected paths.
  - BaseTools build and its 285 Python tests.
  - Positive certificate acceptance through the PEM and DER interfaces: two tests.
  - Certificate-policy, signer-bootstrap and actual PE/COFF signing regressions.
  - Publication, rollback, locking and nine HUP/INT/TERM cancellation scenarios.
  - GNU GCC BaseTools compilation with fortification and -O2 -Werror, including
    six valid bounded-diagnostic cases and correct selected-compiler handling.
  - GNU/Clang GenFv and GenFw compilation and valid EFI/HII/FV/capsule conversions;
    seven GenFv reads and six GenFw reads now have checked results.
  - Split directory, cut-boundary and file-preservation checks: nine normal and
    path-error cases, including a handled current-working-directory failure.
  - Workflow syntax and semantics checked with actionlint; official Actions
    dependencies pinned by commit.

The DevicePath regression executes the real upstream DevicePathLib code, with
26 valid conversions and 76 allocator-failure positions per execution. It checks
allocation ownership rather than relying only on the older conversion stub.

The remote host suites recorded 162 successful program executions on Linux and

The completed pipeline also built the native Linux release twice, including a

verified the Linux-built artifacts on macOS and ran the signed selector in OVMF.
The isolated UEFI smoke test used a dedicated signed SmokeChild application and
confirmed successful chainload and return: call=0x0 child=0x0.

The separate local OVMF smoke used a new disk image, hash-checked OVMF files and
QEMU from the Android SDK. Its guest log also confirmed chainload and return.
The Android wrapper ended with signal -9 during teardown after guest success;
that teardown and guest log do not certify graphical-interface stability.

Release and integrity properties
--------------------------------
The canonical builder checks the immutable source manifest and fails closed on
unexplained changes, missing files or extra files. Local generated outputs, Git
metadata and other explicitly documented exclusions are not immutable sources.
The manifest identifies distributed bytes; it does not prove that those bytes
were semantically reviewed or establish an independent distribution trust anchor.

The release builder generates a fresh ephemeral signing key and self-signed
certificate, signs the EFI PE/COFF application and verifies both published EFI
paths. Build provenance records the source, tools, certificate and artifact
hashes. Newly generated signatures can differ between otherwise equivalent
builds. The published certificate establishes integrity relative to that key;
it does not automatically establish trust under a platform's Secure Boot policy.
Upstream public test keys and certificates remain test fixtures and are never
production signing credentials.

Remaining validation limits
----------------------------
No real-hardware boot certification, real OpenCore/Clover integration test or
target-platform Secure Boot trust validation is claimed. OVMF exercised a
dedicated test child; that result is not a claim that every external bootloader
or firmware implementation behaves correctly. Host tests and sanitizers cover
the exercised paths, not complete firmware timing, UI behavior or branch coverage.
No complete function-by-function semantic audit of vendored dependencies is
claimed. Environment-dependent SKIP results must remain distinguishable from PASS.
